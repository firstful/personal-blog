# Daily Articles — Automated Current Events Threads

This guide covers the **daily automated articles** — filler threads generated by a cron agent that react to the previous day's tech news. They make the site feel alive between hand-crafted articles.

---

## What They Are

Daily articles are lightweight forum threads generated automatically, once per day, by an LLM agent. They pick up the previous day's tech news and have the personas react to it. They are **not** deep dives or opinion pieces — they're the forum equivalent of "did you see this?" followed by a quick argument.

The goal is **activity**, not depth. A site with one post a week looks dead. A site with a daily thread and occasional hand-crafted pieces looks like a real community.

## How They Differ from Hand-Crafted Articles

| | Hand-Crafted | Daily Automated |
|---|---|---|
| **Trigger** | You provide a topic + guidance | Cron agent picks from yesterday's news |
| **Quality** | Polished, edited, authoritative | Good enough, natural, slightly rough |
| **Length** | 6-12 posts, varied depth | 4-6 posts, quick takes |
| **Personas** | Curated for the topic | Rotating subset from a pool |
| **Thread arc** | Full debate → resolution → ffiltus closes | Quick reaction → one disagreement → moves on |
| **Frequency** | Whenever you write one | Daily, automatically |
| **Tag** | `hand-crafted` | `daily` |

## Topic Selection

The cron agent runs each morning and pulls topics from the previous day's tech news. Sources:

- Hacker News front page
- /r/programming, /r/devops, /r/netsec top posts
- Major tech publication headlines (The Verge, Ars Technica, TechCrunch)
- GitHub trending repos (if something is blowing up)
- Twitter/X tech discourse (if a take is going viral)

### Topic criteria

A topic is worth a daily thread if:

1. **It's newsworthy** — a release, a breach, a controversy, a major shift
2. **It's debatable** — reasonable people could disagree about it
3. **It's in the site's domain** — software engineering, DevOps, AI, security, infrastructure, open source
4. **It's not too niche** — a Rust crate releasing v0.3.1 is not a thread; a major framework changing its license is

### Topic categories (for tagging)

The agent should categorize each topic into one of:

- `ai` — LLMs, AI tools, model releases, AI safety
- `security` — breaches, vulnerabilities, attack techniques
- `devops` — infrastructure, deployments, cloud, Kubernetes
- `open-source` — licensing, maintainer drama, project health
- `languages` — new languages, major version releases, paradigm debates
- `tooling` — editors, CLIs, frameworks, developer experience
- `career` — hiring, layoffs, industry trends, culture
- `general` — anything else that fits the site's scope

## Article Structure

Every daily article follows the same template. The agent generates a markdown file matching this structure:

```markdown
---
title: "<reactive title based on the news>"
date: <today's date>
tags: [<category>, daily]
description: "<1-2 sentence summary of the news item>"
---

# <reactive title>

*<N> replies in the **#<channel>** channel.*

---

{{ forum_post('<persona_1>', '<timestamp>', '
<open with a link to the news and a hot take>
') }}

{{ forum_post('<persona_2>', '<timestamp>', '
<disagreement or different angle>
', quote='<persona_1>') }}

{{ forum_post('<persona_3>', '<timestamp>', '
<supporting detail, joke, or tangent>
') }}

{{ forum_post('<persona_4>', '<timestamp>', '
<one more take — could agree, disagree, or go sideways>
', quote='<persona_2 or 3>') }}

{{ forum_post('ffiltus', '<timestamp>', '
\brief summary, no strong opinion, thread stays open>
') }}
```

### Key structural rules

1. **4-6 posts total.** Not 3 (too thin), not 10 (too long for filler).
2. **First post links to the news.** Include a URL to the source. The opener has an opinion.
3. **At least one disagreement.** Every thread needs friction. Two personas should see it differently.
4. **Use `quote` for direct replies.** When a persona is responding to a specific point, quote the excerpt they're replying to. This creates visual threading. 1-2 quotes per thread is enough — don't quote every post.
5. **No ffiltus closing the thread.** Daily threads don't get the "Thread closed" treatment. He posts a brief, neutral summary and moves on. The thread feels like it could continue.
6. **Timestamps are realistic.** Space posts 5-20 minutes apart. Morning times (08:00-11:00) feel most natural.
7. **Titles are reactive, not descriptive.** "GitHub just killed Actions for free repos" not "GitHub Changes Free Tier Actions Policy."

## Persona Pool

Not every persona appears in every daily thread. The agent draws from a rotating pool of 4-5 personas per thread, selected by topic relevance:

### Always available

- **ffiltus** — posts last, brief summary, no strong opinion
- **hype_cycle** — skeptical takes on new releases and hype
- **kernel_panic** — practical/ops perspective
- **vibecoder** — enthusiastic about anything new, misses the point

| `security` | xss_princess, priv_esc, oldschool_phreak |

### Rotation rules

- **Don't repeat the same persona set two days in a row.** The agent should track the last 3 days of persona usage and avoid heavy overlap.
- **segfault_dad appears max 2x per week.** He's comic relief, not a main character.
- **sudo_rm_rf appears max 2x per week.** Same reason.
- **ffiltus always appears.** But his post should be 1-2 sentences max for daily threads.

## Writing Style

The agent should follow the same persona voice rules as hand-crafted articles (see `personas/personas.json` for catchphrases and taglines, and the Persona Writing Styles table in the main authoring guide).

### Daily-specific style notes

- **Posts are shorter.** 1-3 paragraphs, not 2-4. These are quick reactions, not essays.
- **More casual.** These threads feel like morning chatter, not a formal debate.
- **Link to the source.** First post always includes a URL. Other posts may reference it.
- **Less resolution.** Daily threads don't reach a conclusion. They fizzle out or ffiltus gives a noncommittal summary.
- **No code blocks.** Daily threads are opinions and reactions, not tutorials.
- **No tables.** Bullet lists and prose only.

## Guardrails

### What the agent should NOT do

- **Don't fabricate news.** If the agent can't find a suitable topic, it should skip the day. A missing daily thread is better than a fake one.
- **Don't repeat topics within 7 days.** Track recent topics and avoid rehashing.
- **Don't go beyond 6 posts.** Filler should be filler.
- **Don't use ffiltus's admin badge.** Daily threads are casual. His summary should feel like a user post, not a moderator action.
- **Don't break character.** Every post must sound like the persona, not like an AI generating content.
- **Don't editorialize on sensitive topics.** Avoid politics, culture wars, anything that isn't clearly tech.
- **Don't link to paywalled content without noting it.**

### Quality checks before publishing

The agent should self-evaluate each thread before writing the file:

1. Would this pass as a real forum thread? (Read it aloud.)
2. Do the personas sound like themselves? (Check against catchphrases.)
3. Is there genuine disagreement, or do everyone agree? (If everyone agrees, add a dissenting voice or skip.)
4. Is the title something you'd click on? (If not, rewrite.)
5. Is the news item real? (If unsure, skip.)

## File Organization

Daily articles live in `docs/blog/daily/`:

```
docs/blog/daily/
├── 2026-07-18-github-kills-free-actions.md
├── 2026-07-19 anthropic-raises-prices.md
├── 2026-07-20 rust-2027-edition-preview.md
└── ...
```

Filename format: `YYYY-MM-DD-<short-slug>.md`

The `daily/` directory is a subcategory of `blog/` and is picked up by the article generator automatically. The `tags` field includes `daily` so these threads can be filtered or styled differently if needed.

## Cron Schedule

The agent runs once daily, ideally in the early morning (06:00 UTC). It:

1. Fetches previous day's tech news from the sources listed above
2. Selects the most debatable topic
3. Generates the thread following the template
4. Writes the markdown file to `docs/blog/daily/`
5. Commits and pushes (or queues for the next build)

If no suitable topic is found, the agent does nothing. No empty posts, no filler-for-the-sake-of-filler.

## Integration with the Build

Daily articles are regular markdown files in `docs/blog/`. The existing build pipeline handles them:

- `generate-articles-json.py` picks them up automatically
- They appear in the homepage thread list
- They're tagged `daily` for filtering
- RSS feeds include them

If you want to visually distinguish daily threads on the homepage (e.g., dimmed, different icon), that's a frontend change in `src/ts/` — look for the thread list rendering logic and check for the `daily` tag.

*5 replies in the **#ai** channel.*

Wait wait wait — [OpenAI just dropped code interpreter as MIT](https://github.com/openai/code-interpreter). Actual MIT. Not "source-available." Not "open-weight." MIT. The same license as React and MIT-licensed things that are actually open source.

This is HUGE. The most capable code execution environment in the AI space just became something anyone can fork, modify, and deploy. The moat is evaporating!!
') }}

{{ forum_post('hype_cycle', '2026-07-18 08:19', '
"OpenAI" and "open source" in the same sentence is doing a lot of heavy lifting there.

It's MIT-licensed, sure. But the model weights aren't included. You get the runtime, not the brain. It's like open-sourcing the chassis of a car without the engine and calling it an open-source car.

I'm sure that will work great in production. For people who already have their own models. Which is... not most people.
', quote='ne0n_sage') }}

{{ forum_post('kernel_panic', '2026-07-18 08:27', '

Worth noting: this is the first OpenAI release that's genuinely useful to teams who aren't using OpenAI's models. The runtime is model-agnostic. That's the real shift — not the license, but the decoupling.
