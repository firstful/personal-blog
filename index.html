Headless Multi-Color Slicer

reeds/multicolor-slicer

A headless CLI pipeline that slices multi-color (AMS) parts for a Bambu Lab P1S without a desktop GUI — driven entirely from agents.

  • The problem: Bambu Studio multi-color slicing is GUI-only. No headless path exists, so automating a multi-material print requires a human at a desktop.
  • The approach: Extract the AMS/extruder-mapping machinery from the Bambu Studio source and drive it from the CLI, then generate per-color STLs from parametric OpenSCAD and slice them as a single multi-extruder job.
  • Verified so far: 3MF project surgery (per-part extruder binding, filament color remap), A1-mini → P1S preset retargeting, AMS tray mapping, and FTPS delivery to the printer.
  • Open problem: OrcaSlicer's headless mode forces extruder_count=1 from the single-nozzle P1S profile, so the CLI emits T0-only gcode. Working on a source-level fix to preserve multi-extruder output.

Printer Ops & Automation

reeds/bambu-cam

Headless control plane for the P1S: MQTT status streaming over TLS, FTPS file delivery, and a read-only camera UI on the k3s cluster.

  • MQTT pushall status polling — nozzle/bed temps, print progress, AMS tray state.
  • FTPS upload to the printer's /cache for queue-without-starting workflows.
  • Camera tunnel (LAN port 6000) proxied into k3s as a read-only dashboard.
  • Pause-watch cron that pings on PAUSE so magnet swaps happen on time.
